# APEX PREDATOR
## HyperPlanner Beginner Movement-Access & Strength Plan

**Status:** Training-design baseline before implementation specification  
**Primary goal:** assess basic movement access, identify meaningful restrictions/asymmetries, and progressively train strength through accessible ranges  
**Audience:** beginners and early intermediates  
**Duration:** 12 weeks  
**Frequency:** 3 days/week recommended; 2-day minimum may be considered but should not be default  
**Format:** full-body training + small dynamically selected movement-access modules  
**Relationship:** beginner movement-quality pathway that can naturally lead into **Immaculate (Re)Structure**

---

# 1. Core Identity

> **FIND THE RESTRICTION. LOAD THE RANGE. BECOME HARDER TO BREAK.**

APEX PREDATOR is not a rehabilitation program and should not present itself as one.

It does not diagnose:

- injuries;
- pathology;
- impingement;
- instability;
- anatomical defects.

It evaluates simple repeatable movement-access tasks, records left/right differences where relevant, and uses the results to influence exercise emphasis.

The programming model is:

> **Assess → Load → Control → Retest**

This is intentionally different from:

> assess → static stretch → reassess.

The program should primarily improve movement access through controlled loaded training.

---

# 2. Relationship to Other Programs

## From Skeleton to Threat
**Learn to train.**

Simple beginner progression.

## Apex Predator
**Learn how your body moves.**

Movement-access assessment + beginner full-body training.

## Immaculate (Re)Structure
**Investigate and rebuild specific structural weaknesses.**

More advanced structural relationships, strength ratios and individualized weak-link programming.

Apex should feel like the junior entry point into that ecosystem.

---

# 3. Program Structure

**12 weeks**

## Week 0 / Onboarding
Initial movement-access assessment.

## Weeks 1–3 — STALK
Learn exercises and begin weak-area emphasis.

## Week 4 — FIRST HUNT
Retest movement profile.

## Weeks 5–7 — ADAPT
Update emphasis based on new assessment.

## Week 8 — SECOND HUNT
Retest.

## Weeks 9–11 — APEX
Highest normal training effort.

## Week 12 — FINAL HUNT
Final assessment + reduced-volume training + next-plan recommendation.

---

# 4. Assessment Design Principles

The assessment battery should be:

- short;
- repeatable;
- understandable without a coach;
- measurable in a simple way;
- resistant to fake precision;
- usable on left/right sides where relevant.

Avoid an enormous FMS-style battery.

Target:

**6–8 tests maximum.**

The app should track:

- movement access;
- side-to-side difference;
- change over time;
- test confidence/validity if needed.

Do not automatically interpret restricted range as pathology.

---

# 5. Proposed Assessment Battery

## Test 1 — Ankle Dorsiflexion Access

### Method
Knee-to-wall style test.

User:
- keeps heel down;
- moves knee forward toward wall;
- finds the greatest repeatable distance they can achieve without heel lift.

Track separately:

- Left
- Right

Preferred measurement:

**toe-to-wall distance in cm**

If measurement is impractical, use a simple ordinal score.

### Programming influence
A lower score may increase emphasis on:

- forward-knee split squat variations;
- controlled calf work through long ROM;
- loaded ankle rocks;
- gradually reduced heel elevation.

---

# 6. Test 2 — Active Straight-Leg Raise / Hip-Flexion Access

Simple floor test.

Track:
- Left
- Right

Prefer a simple visual scoring system rather than pretending the phone knows exact degrees without camera analysis.

Example internal scale:

- Level 1 — clearly limited
- Level 2 — moderate access
- Level 3 — good access

### Programming influence

Potential movements:

- Hip-Supported DB Deadlift
- controlled RDL
- supported single-leg RDL
- long-ROM hamstring work
- active leg-raise practice

---

# 7. Test 3 — Hip Rotation Access

Seated or supported hip-rotation assessment.

Track:

- Left internal-rotation access
- Right internal-rotation access
- Left external-rotation access
- Right external-rotation access

For beginner UX, these can be summarized into:

```text
HIP ROTATION

LEFT   2/3
RIGHT  1/3
```

### Programming influence

Possible tools:

- 90/90 transitions;
- supported hip rotations;
- Goblet Skater Squats;
- split squats;
- unilateral hinge work.

---

# 8. Test 4 — Shoulder Flexion Access

Simple wall-based overhead reach.

Key idea:

raise straight arms overhead while minimizing obvious compensations.

Score using a simple repeatable level.

### Programming influence

Potential exercises:

- DB Pullover with progressive ROM;
- wall slide;
- half-kneeling single-arm press;
- controlled overhead carry if appropriate;
- gradual overhead ROM exposure.

---

# 9. Test 5 — Shoulder Rotation Access

Use a simple functional external-rotation/reach task.

Track:

- Left
- Right

Avoid medical interpretation.

### Programming influence

Potential exercises:

- controlled DB external rotation;
- rear-delt work;
- face-pull-type patterns where equipment exists;
- pressing variation selection;
- shoulder-control work.

---

# 10. Test 6 — Thoracic Rotation Access

Use a seated or quadruped rotation test.

Track:

- Left
- Right

### Programming influence

Potential exercises:

- open-book rotation;
- quadruped rotation;
- rotational row;
- half-kneeling single-arm press;
- unilateral pulling.

---

# 11. Test 7 — Squat Access

This should be treated as a **pattern-access test**, not a single-joint mobility diagnosis.

Observe simple elements:

- depth;
- heel contact;
- trunk control;
- obvious left/right shift;
- knee tracking.

Output should remain descriptive.

Example:

```text
SQUAT ACCESS
Depth: 2/3
Heel contact: PASS
Shift: LEFT
```

Do not infer:

> ankle restriction caused the squat problem

unless separate test data supports that relationship.

### Programming influence

Can alter:

- heel elevation;
- squat variation;
- unilateral emphasis;
- ROM starting point.

---

# 12. Optional Test 8 — Behind-Back / Shoulder Internal-Rotation Reach

Include only if onboarding remains short enough.

This is lower priority than:

- ankle;
- hip rotation;
- shoulder flexion;
- thoracic rotation.

If the assessment battery becomes too long, remove this first.

---

# 13. Pain / Invalid-Test Handling

Every test should ask:

> Did this produce pain?

Options:

- No
- Mild discomfort/stretch only
- Pain

If the user selects **Pain**:

- stop that test;
- do not assign a "mobility correction" from it;
- mark result as invalid;
- show a neutral recommendation to avoid forcing the painful position and seek appropriate professional assessment if needed.

The app should not diagnose the cause.

---

# 14. Scoring Philosophy

Do not generate fake precision like:

> Mobility = 73.4%

Prefer region-based levels.

Example:

```text
MOVEMENT PROFILE

ANKLES        ●●○
HIPS          ●○○
T-SPINE       ●●○
SHOULDERS     ●●○
SQUAT ACCESS  ●●○
```

Possible theme classifications:

## CAGED
Several restricted patterns.

## HUNTER
Fundamental positions becoming accessible.

## PREDATOR
Good access and control across most tests.

## APEX
Strong movement access with minimal meaningful asymmetry.

These classifications are gamification, not medical labels.

---

# 15. Asymmetry Logic

Apex should pay attention to meaningful left/right difference.

Do not automatically prescribe huge extra volume.

Possible rule:

- weaker/restricted side goes first;
- add one small control/mobility set to the lower-scoring side when appropriate;
- reassess at checkpoints.

Examples:

- single-arm pulldown;
- single-leg split squat;
- unilateral carry;
- supported single-leg hinge.

The goal is modest rebalancing, not punishment volume.

---

# 16. Base Training Structure

Apex should remain a real beginner hypertrophy/strength program.

Recommended:

**3 full-body days/week**

Target:

**13–16 working sets/session**

Each session contains:

1. knee-dominant movement;
2. hinge;
3. push;
4. pull;
5. one or two accessories;
6. 1–2 dynamically selected movement-access exercises.

Do not let the dynamic mobility module dominate the workout.

# 20. Dynamic Access Slots

The app selects from the user's **two lowest valid movement regions**.

Each region gets:

- one small dynamic-access slot;
- typically 1–2 sets;
- often attached to an existing exercise rather than creating excessive extra work.

Examples:

## Ankle limitation

Potential injection:

- Loaded Knee-Over-Toe Split Squat
- controlled ankle-rock variation
- long-ROM calf work

## Hip-flexion / hamstring access

- supported long-ROM RDL
- active straight-leg raise
- controlled single-leg hinge

## Hip rotation

- 90/90 transition
- supported hip rotation
- Goblet Skater Squat

## Shoulder flexion

- DB Pullover with progressive ROM
- wall slide
- half-kneeling single-arm press

## Thoracic rotation

- open-book
- quadruped rotation
- rotational row

Dynamic work should be **loaded or controlled movement where possible**, not endless passive stretching.

---

# 21. Progressive-ROM System

The app should track usable range on selected movements.

Examples:

## Pullover

Week 1:
stop before compensatory rib flare.

Week 4:
slightly greater controlled shoulder-flexion ROM.

## Split Squat

Week 1:
comfortable knee travel.

Later:
progressively deeper front-knee travel if ankle access improves.

## RDL

Week 1:
stop at controlled hamstring limit.

Later:
increase ROM without lumbar compensation.

HyperPlanner should treat ROM as a progression variable.

---

# 22. Test-to-Exercise Mapping

Use a mapping table rather than hard-coded conditionals scattered through the app.

Conceptually:

```text
movementRegion:
  ankle:
    preferredExercises:
      - kneeOverToeSplitSquat
      - longRomCalf
      - ankleRock

  shoulderFlexion:
    preferredExercises:
      - dbPullover
      - wallSlide
      - halfKneelingPress

  thoracicRotation:
    preferredExercises:
      - openBook
      - quadrupedRotation
      - rotationalRow
```

Each mapping should include:

- exercise ID;
- equipment requirement;
- difficulty;
- whether unilateral;
- contraindication/pain guard;
- progression type.

---

# 23. Retest Schedule

Do not retest every workout.

Recommended:

## Initial
Week 0.

## Checkpoint 1
End of Week 4.

## Checkpoint 2
End of Week 8.

## Final
Week 12.

This reduces noise and annoyance.

---

# 24. Dynamic Reallocation After Retest

After a checkpoint:

1. compare new valid scores with previous scores;
2. identify the two lowest current regions;
3. check asymmetries;
4. update movement-access exercise slots for the next block.

Example:

```text
Week 0
Ankle: low
Shoulder flexion: low

Weeks 1–4 emphasis:
ankle + shoulder

Week 4
Ankle: improved
Shoulder: improved
Hip rotation now lowest

Weeks 5–8 emphasis:
hip rotation + shoulder
```

This is the program's main app-native behavior.

---

# 25. Training Progression

Base strength/hypertrophy movements should remain simple.

Use:

**double progression**

Example:

3×8–12

Top of range on all sets with acceptable technique:

> increase load.

For beginners, avoid complicated percentage prescriptions.

The program is already cognitively rich because of the assessment system.

Do not add unnecessary loading complexity.

---

# 26. Phases

## Weeks 1–3 — STALK

- 2–3 RIR;
- learn base exercises;
- use first weak-region assignment.

## Week 4 — FIRST HUNT

- reduce accessory volume slightly;
- retest movement profile;
- update dynamic slots.

## Weeks 5–7 — ADAPT

- 1–2 RIR;
- continue double progression;
- new weak-region emphasis.

## Week 8 — SECOND HUNT

- retest;
- update emphasis.

## Weeks 9–11 — APEX

- hardest normal phase;
- final sets of selected safe isolations may reach 0–1 RIR;
- loaded mobility movements continue controlled, not maximal.

## Week 12 — FINAL HUNT

- reduce lifting volume ~30–40%;
- final assessment;
- compare movement profile;
- recommend next plan.

# 31. Naming / Theme Integration

The white Bengal tiger-human hunter theme fits the program well if used as:

> evolving from restricted movement into efficient predatory movement.

Avoid implying that a high "mobility score" makes someone biologically superior.

Theme terms can include:

- Stalk
- Hunt
- Adapt
- Predator
- Apex

without changing the underlying training language.

---

# 32. App-Native Mechanics

Apex Predator should have five signature systems:

## 1. Movement Assessment Battery
Short, repeatable tests.

## 2. Left/Right Tracking
Where relevant.

## 3. Weak-Region Selection
Identifies the two lowest valid regions.

## 4. Dynamic Access Injection
Adds small targeted movement slots.

## 5. Retest / Reallocation
Every four weeks the emphasis can change.

This makes Apex substantially more than a themed beginner plan.

---

# 33. Guardrails

The app should never say:

- "You have shoulder impingement."
- "Your hip is dysfunctional."
- "Your pelvis is misaligned."
- "This asymmetry is causing your pain."

Use:

- restricted access;
- lower current score;
- side-to-side difference;
- movement emphasis;
- controlled progression.

If pain occurs during a test, mark it invalid and stop using that test to generate training advice.

# 35. Decisions Considered Locked

- Name: **APEX PREDATOR**
- beginner/early-intermediate
- 12 weeks
- 3-day full-body default
- movement-access assessment
- 6–8 tests maximum
- left/right tracking where relevant
- no medical diagnosis
- pain makes a test invalid
- two lowest valid regions influence training
- small dynamic movement-access modules
- retest Weeks 4, 8 and 12
- loaded/controlled movement preferred over passive stretching
- simple double progression for normal strength work
- designed as a natural precursor to Immaculate (Re)Structure

# 36. Remaining Questions Before Claude Spec

1. Which exact six tests should be mandatory?
2. Should squat-access be a scored test or a descriptive pattern screen only?
3. Should ankle dorsiflexion use cm only or also support a 1–3 fallback score?
4. How should hip rotation be measured without camera analysis?
5. Should the optional eighth shoulder test be cut to keep onboarding short?
6. What threshold defines a meaningful asymmetry for each test?
7. Should two weak regions always be selected, or only regions below a minimum level?
8. How many dynamic-access sets are enough without turning Apex into a mobility program?
9. Which access exercises already exist in the exercise database?
10. Should Week 12 automatically offer Immaculate as the default next plan if multiple restrictions persist?

---

# 37. Guiding Principle

> **APEX PREDATOR should make a beginner stronger through the range they can control, then gradually expand that range and prove the change with repeatable tests.**
